## Added file: api/notes.js

This is the server-side Vercel function. Database credentials remain on the server.

- `GET /api/notes`: returns the newest 100 approved filenames.
- `GET /api/notes?filename=...`: returns one approved note. Pending/rejected/missing
  notes all return a not-found response.
- `POST /api/notes`: validates filename, author, message, content type, size,
  request ID, and selected control characters; then inserts a pending note.
- Parameterized SQL keeps submitted text separate from SQL instructions.
- A duplicate filename returns 409. Matching retries return success without
  duplicating the note. Unsupported methods return 405.
- Limits submissions to three attempts per client address per fixed clock hour,
  using atomic database counters. Existing matching retries bypass this counter.
- Stores keyed address hashes rather than raw IP addresses. Old rate counters
  are removed on later submissions. Client hashes on note records are retained
  to verify retries; they are never returned by the public API.
- Adds no-store and content-type headers. Selected cross-site browser submissions
  are rejected. There are no public approval/rejection operations.
- Returns a generic service error without exposing database credentials or raw
  database exceptions. This is basic abuse protection, not a CAPTCHA or login system.
